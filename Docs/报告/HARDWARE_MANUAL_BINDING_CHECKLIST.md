# Phase 3 真实硬件人工绑定检查表

## 1. 适用范围与当前结论

本检查表用于后续有真实电气图纸、确定型号和授权工程师参与时，将当前绿地工程绑定到生产硬件。Phase 3 仅建立离线 NC 轴、PLC `AXIS_REF` 和占位 I/O；未扫描设备、未创建 EtherCAT/I/O/Safety 工程、未绑定驱动或端子、未激活配置、未下载、未登录运行时。

当前结论：**不得用于生产运行**。`GVL_Status.bProductionReady` 固定初值为 `FALSE`，`ST_HardwareBindingStatus` 的全部字段也保持默认 `FALSE`。只有以下条目全部由授权人员完成并形成证据后，后续业务逻辑才可以计算生产就绪状态。

## 2. 已完成的内部工程准备

- [x] 创建离线 NC 任务 `NC_Cff SAF`。
- [x] 创建两个未绑定真实驱动的 NC 轴：`Z_Axis_NC`、`R_Axis_NC`。
- [x] 将 `GVL_IO.Z_axis.PlcToNc/NcToPlc` 与 `Z_Axis_NC` 的内部过程映像双向连接。
- [x] 将 `GVL_IO.R_axis.PlcToNc/NcToPlc` 与 `R_Axis_NC` 的内部过程映像双向连接。
- [x] 将 `Task_CffFast` 同步到 NC SAF 的实际周期：`20000 × 100 ns = 2000 us`。
- [x] 所有占位 I/O 使用 `%I*`/`%Q*`，没有硬编码物理地址。
- [x] 工程中不存在 I/O 设备配置和 Safety 配置；XAE 可为映射基础设施序列化空 `<Io/>` 容器。

以上勾选只证明离线工程内部结构已经建立，不代表任何真实硬件有效。

## 4. Z 轴真实绑定

- [ ] 在经批准的目标工程中人工添加正确的 EtherCAT 主站、耦合器和 Z 轴驱动，不使用设备扫描替代图纸核对。
- [ ] 将 `Z_Axis_NC` 的编码器和驱动过程数据链接到唯一的实际设备通道。
- [ ] 核对编码器分辨率、丝杠导程/传动比、工程单位和位置方向；工程约定向下为正。
- [ ] 核对额定/最大速度、加速度、减速度、急停减速度和软限位。
- [ ] 核对使能、正负向进给许可、制动器控制及驱动故障复位链。
- [ ] 核对原点、参考点、硬限位和触碰/碰撞相关输入的极性。
- [ ] 验证外部设定值模式的使能、送值、禁用和异常退出生命周期。
- [ ] 低速点动验证位置反馈方向；随后验证绝对定位、停止和复位，不进行工艺负载测试。
- [ ] 证据归档后允许后续逻辑置 `bZAxisDriveLinked`，否则保持 `FALSE`。

## 5. R 轴真实绑定

- [ ] 人工添加正确的 R 轴驱动并链接 `R_Axis_NC` 的编码器和驱动过程数据。
- [ ] 核对编码器分辨率、传动比、转速单位、旋转正方向和扭矩单位。
- [ ] 核对额定/最大转速、加减速斜坡、扭矩限值和驱动保护参数。

- [ ] 低速空载验证转速方向、实际转速、扭矩反馈和受控停止。
- [ ] 证据归档后允许后续逻辑置 `bRAxisDriveLinked`，否则保持 `FALSE`。

## 6. 传感器与外围 I/O

- [ ] 将 `nForceChannelRaw` 映射到唯一的EP3174力输入，并分别映射`bForceChannelError`、`bForceChannelOverrange`和`bForceChannelUnderrange`；核对数据类型、量程、Extended/Legacy Range和断线诊断。
- [ ] 将 `nDisplacementChannelRaw` 映射到唯一的位移传感器输入，并分别映射Error/Overrange/Underrange诊断，核对方向和量程。
- [ ] 将 `bCollisionReferenceSensor` 映射到经风险评估确认的Collision Reference Sensor，并核对常态电平、去抖时间与断线安全行为；旧占位`bCollisionDetected`不得替代该标定输入。
- [ ] 完成紧固件、供料器、夹具、机器人许可等输入映射，并逐点验证。
- [ ] 完成供料、夹紧、机器人就绪和塔灯输出映射；第一次输出测试必须在执行机构隔离条件下进行。
- [ ] 对所有输入执行强制断开、短接或模拟量边界测试，并保留结果。
- [ ] 对所有输出执行单点受控测试，确认不会绕过安全链或造成机构动作冲突。
- [ ] 力、位移和碰撞输入分别完成后，才允许后续逻辑置对应 `Mapped` 字段。
- [ ] 所有外围 I/O 完成后，才允许后续逻辑置 `bPeripheralIoMapped`。

## 7. 安全与生产释放门槛

- [ ] 安全工程由具备资质的人员在独立批准流程中完成；本仓库 Phase 3 没有创建 TwinSAFE 项目。
- [ ] 验证急停、防护门、安全速度/停止、驱动 STO、气源卸压和安全复位。
- [ ] 验证普通 PLC 只读取经批准的安全状态，不替代安全逻辑。
- [ ] 完成冷态、空载、低能量、单循环和故障注入测试。
- [ ] 完成轴、传感器、外围 I/O、标定、程序数据和安全验收的交叉签字。
- [ ] `bProductionHardwareBindingComplete` 只能由确定性的验证逻辑计算，不得人工强制或默认置真。
- [ ] `GVL_Status.bProductionReady` 必须同时依赖硬件绑定、标定、程序快照、安全许可和无活动故障；任一条件失效立即为 `FALSE`。
